[Claude Code](https://code.claude.com/docs) is a terminal app. It runs on one machine, in one terminal, and the conversation lives there. [RClaude](https://github.com/Lunat1q/RClaude) moves it onto a server and gives you four ways in:

- a **web terminal** with the real `claude` TUI,
- a **phone-friendly chat view**,
- a **REST API**,
- an **MCP server**, so other agents (a claude.ai connector, another Claude Code) can start and continue sessions.

It's self-hosted, single-user, and ships as one Docker image.

![The real Claude Code TUI running in the browser](/assets/img/rclaude/claude-terminal.png)

## Two ways to work

**Terminal mode** is the actual interactive Claude Code console: xterm.js in the browser, a WebSocket, and a PTY on the server. Terminals keep running when you close the tab, so you can start something on the laptop and reattach from another device. There's also a plain shell next to it.

**Chat mode** is built on the [Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk). It streams replies, and tool permission prompts and Claude's questions show up as buttons instead of keystrokes. That's the one to use on a phone.

Both are normal Claude Code sessions, saved in the usual `~/.claude/projects/...` history. A conversation started in one mode can be resumed in the other, and the sidebar lists, renames and deletes them.

![New session: Claude terminal, chat or shell, in any folder](/assets/img/rclaude/new-session.png)

On a phone the terminal gets a key bar (Esc, Tab, Ctrl+C, arrows) and a text input, because a phone keyboard has none of those.

![Terminal on a phone with the on-screen key bar](/assets/img/rclaude/mobile-terminal.png){: w="300" }

## API and MCP

Everything the UI does is also a REST endpoint: start a chat, send a message, wait for the turn to finish, answer a permission prompt, read the transcript. Authentication is a bearer token you create in Settings.

```sh
curl -s -H "Authorization: Bearer $RCLAUDE_TOKEN" -H 'content-type: application/json' \
  -d '{"prompt":"Summarize the README in this repo","cwd":"myproject","wait":120}' \
  https://claude.example.com/api/chats
```

The MCP endpoint (`/mcp`, Streamable HTTP) exposes the same as tools: `start_session`, `send_message`, `wait_for_session`, `respond_permission`, `get_transcript` and a few more. You can add it to claude.ai as a custom connector (it signs in through OAuth 2.1 with your RClaude password), or to Claude Code with an API token:

```sh
claude mcp add --transport http rclaude https://claude.example.com/mcp \
  --header "Authorization: Bearer rck_..."
```

So a Claude on one machine can hand work to the Claude Code on the server and check back later.

![Settings: Claude account status, MCP URL, API tokens](/assets/img/rclaude/settings.png)

## Auth

There's one account. On first login the UI asks for a setup code from the server's environment and a new password, and after that setup is disabled. Logins are rate-limited per IP with exponential lockout. The web UI uses an HttpOnly, SameSite=Strict cookie; the API and MCP use bearer tokens or OAuth.

Optionally it can sit behind a forward-auth proxy such as authentik. RClaude then verifies the signed ID token the proxy passes (signature, issuer, audience, expiry and the one allowed email) and skips its own login form.

> Whoever gets past the login has a shell and a Claude Code with full tool access in the container. Use a strong password, keep the setup code secret, and consider SSO in front of it.
{: .prompt-warning }

## Host mode

By default Claude and the terminals run inside the container, confined to its two volumes. With `RCLAUDE_HOST_SSH=user@host` they run on the Docker host instead, over SSH, as a real login session of that user: their PATH, their groups, their Claude login and settings. The server only relays the I/O. If you also mount that user's home into the container, the session list shows the host's own Claude Code history, so sessions started locally and remotely are one list.

That's convenient and it's also a lot of power: if the host user has docker or sudo, logging into RClaude is effectively root on the host.

## Install on Coolify

The [README](https://github.com/Lunat1q/RClaude#install-on-coolify) has the full steps. Short version:

1. **+ New → Public Repository**, `https://github.com/Lunat1q/RClaude`, build pack **Dockerfile**, port `3000`.
2. Set a domain, plus two env vars: `PUBLIC_URL` (the exact `https://` domain) and `RCLAUDE_SETUP_CODE` (a long random string).
3. Add two persistent volumes: `/home/claude` (Claude login, history, app database) and `/workspace` (your projects). Without them a redeploy logs Claude out and wipes your code.
4. Deploy, open the domain, enter the setup code, pick a password.
5. In **Settings → Open shell**, run `claude auth login`. Or set `CLAUDE_CODE_OAUTH_TOKEN` / `ANTHROPIC_API_KEY` in the environment.

![First login: setup code and new password](/assets/img/rclaude/setup.png){: w="600" }

Any other Docker host works too; the README has a `docker run` line.

## Limits

- One user. There are no accounts or per-user workspaces.
- Claude Code needs its own login on the server (a subscription login or an API key).
- Without host mode, Claude only has the tools in the image: Node, Python, git, gh, ripgrep, jq and the usual CLI basics. The container user isn't root, so there's no `apt install`. Need more? Extend the Dockerfile or use host mode.
